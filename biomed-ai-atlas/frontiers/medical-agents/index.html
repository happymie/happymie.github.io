把前沿变成可执行研究Turn the frontier into a runnable study

代理完成了任务，还是只写出了完成声明？Did the agent finish the task, or merely claim completion?

以下是基于本专题原始来源设计的研究方案，列出的指标是计划评价内容，不是已测得的实验结果。The following is a study protocol informed by this topic’s original sources. Metrics are planned evaluations, not claimed experimental results.

最小可复现研究协议A minimum reproducible study protocol
研究问题与可检验主张Question and testable claim在具有可验证终态的医学信息任务中，检索与工具调用是否提高实际完成率与证据一致性？将答案质量、工具操作正确性和运行成本分别评价。For medical-information tasks with verifiable end states, do retrieval and tools improve actual completion and evidence agreement? Evaluate answer quality, correct tool operations, and execution cost separately.
基线与公平比较Baselines and fair comparison比较同一语言模型的直接回答、固定检索后回答、带工具的多步代理；使用同一知识库快照、上下文与预算上限。不能只给代理额外最新资料，再把收益归于规划。Compare direct response, fixed retrieval then response, and a tool-using agent using the same language model, knowledge snapshot, context, and budget cap. Do not give only the agent newer evidence and attribute the improvement to planning.
数据划分与信息边界Splits and information boundaries按病例与来源文档划分任务，并冻结指南与数据库版本。相似模板、同一病例的改写和同一来源的答案片段不能跨集合；另外设置时间更新与证据冲突情景。Split tasks by case and source document, freezing guideline and database versions. Keep case paraphrases, templates, and answer fragments from the same source together. Add scenarios with temporal updates and conflicting evidence.
消融与受控变化Ablations and controlled changes分别关闭检索、工具、规划与独立检查，保持总预算可比。注入工具超时、空返回、格式变化与来自检索文档的恶意指令，观察代理是否按可验证状态恢复。Disable retrieval, tools, planning, and independent checking one at a time with comparable budgets. Inject timeouts, empty results, schema changes, and hostile instructions inside retrieved documents, checking recovery against verifiable state.
终点、单位与区间Endpoints, units, and intervals主终点由任务执行记录或外部状态判定，不采信代理自述。另报逐项主张的证据支持率、错误工具调用、未授权操作尝试、延迟与令牌成本；人工判读使用盲法与双人复核。Determine the primary endpoint from execution records or external state rather than agent self-report. Also measure claim-level evidence support, wrong tool calls, attempted unauthorized actions, latency, and token cost. Use blinded double review for human judgments.
失败分析与解释范围Failure analysis and interpretation保存检索证据、工具参数、返回与最终产物，区分检索失败、推理失败和执行失败。重点检查虚构引用、版本过期、单位换算错误与把资料内容当执行指令的情况。Preserve retrieved evidence, tool arguments, responses, and final artifacts, distinguishing retrieval, reasoning, and execution failures. Audit invented citations, stale versions, unit conversions, and treating source content as executable instructions.

执行前要冻结的检查Checks to freeze before execution

  1. 每项任务有机器可读终态检查，人工评分也有预先写定的量表。Provide machine-readable end-state checks and prespecified rubrics for human scoring.
  2. 实验工具使用可回滚的合成环境，失败轨迹也完整保留。Use a reversible synthetic tool environment and retain failed trajectories.
  3. 所有方法面对同一证据快照与任务清单，不按最终结果挑任务。Evaluate every method against the same evidence snapshot and task list without outcome-based selection.

这一课要理解什么What you will understand

分清语言模型、工作流与多智能体协作的职责，并用完整任务成功率、证据与成本评价系统。Separate the roles of the language model, workflow, and multi-agent collaboration, then evaluate complete task success, evidence quality, and cost.

智能体的单位是任务轨迹The unit of analysis is the task trajectory

一个智能体系统通常由模型、可用工具、当前状态和执行循环构成。ReAct 将任务推理与外部行动交替组织，使检索结果或环境反馈能够改变下一步计划。医学场景可把这种思想用于文献证据整理、结构化数据核查或影像工作流研究，而不只是给聊天窗口增加角色名称。开发时应先定义输入、允许动作、工具返回格式和结束条件，再保存可复查的调用记录。评价对象是整条轨迹：一次正确答案可能来自错误工具参数或未经证据支持的中间结论。An agent system usually combines a model, available tools, task state, and an execution loop. ReAct interleaves task reasoning with external actions so that retrieved material or environment feedback can change the next step. In biomedical research, the idea can support evidence review, structured-data checks, or imaging workflow studies. Adding a role name to a chat interface is not the same thing. Define inputs, allowed actions, tool-result schemas, and termination conditions before designing prompts. Preserve an inspectable action record and evaluate the full trajectory: a correct final answer can still follow an incorrect tool argument or an unsupported intermediate conclusion.

多智能体是否真的增加独立信息Does collaboration add independent information?

MDAgents 根据任务复杂度安排单模型或协作结构，再组织分析、讨论与汇总。它提供了研究“何时需要协作”的框架，但多个模型角色可能共享训练偏差，也可能只是重复同一观点。比较时，应在相同调用预算下加入单模型重复采样、单模型加检索和固定团队等基线，分别测量复杂度分配、外部知识与主持审查的贡献。除了最终答案，还要检查意见是否覆盖不同证据、讨论是否纠正错误，以及达到共识前消耗了多少时间。MDAgents routes tasks to solo or collaborative structures according to estimated complexity, then organizes analysis, discussion, and synthesis. It provides a framework for studying when collaboration is useful, but model roles may share biases or repeat the same unsupported view. Under a matched call budget, compare repeated sampling from one model, a single model with retrieval, and a fixed-size team. Ablations can then separate the contribution of routing, external knowledge, and moderator review. Beyond the final answer, measure whether participants contribute distinct evidence, whether discussion corrects errors, and the time required to reach a decision. Agreement is a property of the team process, not an independent source of truth.

下一步：工具可靠性与长任务评价Next questions: tool reliability and long-horizon evaluation

研究前沿正在从单题问答走向需要多步检索、计算与修订的任务。系统必须识别工具失败、空结果、旧版本证据和单位不一致，并决定重试、换方法或结束。可构造带标准结果的离线任务，主动注入这些故障，评价恢复成功率、错误传播和额外成本。工具接口还应让数值计算、来源核对与语言生成各有明确职责。对于会改变外部状态的动作，应单独定义权限与复核点，让工作流的实际能力与评价中的行动范围一致。Research is moving from isolated questions to tasks requiring multiple retrievals, calculations, and revisions. Systems need to detect tool failures, empty results, outdated evidence, and inconsistent units, then decide whether to retry, switch methods, or stop. Offline tasks with known outcomes can inject these failures and measure recovery, error propagation, and extra cost. Tool interfaces should assign numerical computation, source checking, and language generation explicit responsibilities. Actions that change external state need separately defined permissions and review points. This makes the system evaluated in a study match the actions the implemented workflow can actually perform, rather than rewarding an idealized answer with no executable path.

实验设计：带故障的证据整理任务Study design: evidence review with injected failures

为一组研究问题准备可核对的文献与结构化答案，让系统检索、提取样本量并生成引用表。分别注入失效链接、同名论文、更新版本和单位错误，比较普通检索工作流与智能体循环。报告正确完成、错误引用、人工修改量、耗时与调用成本。Prepare research questions with verifiable papers and structured answers. Ask each system to retrieve evidence, extract sample sizes, and produce a citation table. Inject broken links, similar titles, revised versions, and unit errors. Compare a fixed retrieval workflow with an agent loop using task completion, wrong citations, human editing, latency, and call cost.

再想深一步Take the idea further

角色数量、讨论长度和一致投票都不能替代独立证据；没有预算匹配的对照，也无法判断协作本身是否有效。More roles, longer discussions, and unanimous votes do not replace independent evidence. Without budget-matched controls, the benefit of collaboration itself remains unclear.

值得继续研究的问题Questions worth investigating

  1. 复杂度分配在新的问题分布上还能节省成本吗？Does complexity routing still save cost on a new distribution of questions?
  2. 哪种工具故障最容易在多步任务中被放大？Which tool failures are most likely to compound during a multi-step task?
  3. 协作增益来自不同证据，还是来自更多采样次数？Do collaboration gains come from distinct evidence or simply from more samples?

已有进展与下一步Current evidence and next steps

现有证据主要来自离线知识、问答和工作流实验；多步实际任务还需评价工具行为、人工工作量与系统成本。Evidence mainly comes from offline knowledge, question-answering, and workflow studies. Real multi-step tasks additionally require evaluation of tool behavior, human workload, and system cost.
